# 音视频生命周期测试

`callmanager_integration_test` 使用真实本机 TCP socket 检查呼叫控制链路，但不会打开摄像头、麦克风或屏幕采集设备，因此可以在无人值守的桌面构建中稳定运行。

当前覆盖：

1. 未配对来源建立媒体连接后会立即被拒绝，呼叫状态保持 `idle`。
2. 即使来源 IP 与可信设备相同，只要媒体密钥不匹配，挑战应答就会失败，不能触发来电弹窗。
3. 伪造媒体服务端即使完成 TCP 建连并发送挑战，也无法伪造带 HMAC 的接听响应，调用端不会启动采集。
4. 正确媒体密钥可完成双向挑战应答；邀请、接受和拒绝都带 HMAC，接受后才启动采集。
5. 挂断会清除本地与远端帧，并更新 QML 图片版本，下一次会话不会停留在上一帧。
6. 对方拒接后，双方释放 socket 并回到 `idle`。
7. 连接失败会释放当前 socket、退出 `calling`，不会阻塞后续呼叫。
8. 连接失败后可以立即重新发起新的摄像头或屏幕共享呼叫。
9. 在不占用真实采集设备的条件下完成双端接通，任一端挂断后双方都释放 socket、清除帧并回到 `idle`。
10. 已认证媒体 socket 每 5 秒发送空音频心跳；20 秒收不到任何远端数据时主动结束会话、清除最后画面并回到 `idle`，避免 Wi-Fi 切换后的半断开状态永久挂起。

媒体密钥由长期配对密钥单向派生，QML 和 `CallManager` 不接触原配对密钥。媒体 TCP 建连后，接收端先生成 256 位随机挑战；发起端使用派生密钥证明身份，接收端再用带 HMAC 的接受或拒绝响应证明身份。协议只在认证完成且状态正确时接受模式切换、音频帧和视频帧。远端 JPEG 在解码前会检查压缩数据长度、尺寸和像素数，避免异常图片造成过量内存分配。

Android 真机仍需验证摄像头、录音和 MediaProjection 系统授权。权限未授予时，`CallManager` 现在只报告错误，不会直接创建对应的摄像头或麦克风采集对象。

Windows 构建还包含 `application_qml_smoke_test` 和 `call_ui_qml_smoke_test`。两项测试以隐藏窗口方式分别加载主界面和通话界面；对象创建失败、QML 运行期警告或绑定循环都会使测试失败。
