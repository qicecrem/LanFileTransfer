# 配对与连接状态机

连接状态由 `TransferManager` 按设备 ID 统一维护。QML 不再根据 socket 或临时布尔值推断连接状态。

## 状态

| 状态 | 含义 | 可进入的下一状态 |
| --- | --- | --- |
| `unpaired` | 尚未建立信任，或用户已解除配对 | `pairing` |
| `pairing` | 首次连接，等待对方确认 | `online`、`unpaired` |
| `online` | 已信任且控制长连接可用 | `reconnecting`、`unpaired` |
| `reconnecting` | 已信任，正在恢复控制连接 | `online`、`offline`、`unpaired` |
| `offline` | 已信任，但当前不可达 | `reconnecting`、`unpaired` |

## 连接链路

1. UDP 发现以设备 ID 识别对端，并提供最新 IP、文件服务端口和媒体端口。
2. 首次点击设备时进入 `pairing`，TCP 控制连接发送配对请求。
3. 首次请求携带随机生成的 256 位配对密钥；对方人工接受后，双方保存设备信息和配对密钥，并进入 `online`。
4. 控制连接每 15 秒交换心跳；45 秒没有收到任何控制包即判定连接失效。
5. 在线连接断开后进入 `reconnecting`，按 1、2、4、8、16 秒退避重试；连续失败后进入 `offline`。
6. 应用重启后可信设备初始为 `offline`。设备发现服务再次发现它时，使用最新地址自动重连。
7. 已信任设备重连时必须使用随机挑战和 HMAC-SHA256 证明其持有原配对密钥，通过后才会自动接受；仅伪造设备 ID 会被立即断开。未知设备仍必须人工确认。
8. 解除配对会删除持久化信任、取消待执行的重连，并回到 `unpaired`。
9. Android 前台恢复或默认网络、链路属性变化时，发现服务释放旧网卡的组播成员、重新枚举接口并立即广播；发现到可信设备后沿用上述重连流程。
10. 双方同时重连产生两条交叉控制连接时，以设备 ID 排序选举唯一连接：ID 较小的一端保留出站连接，ID 较大的一端保留对应的入站连接；非首选重复连接在握手完成后关闭。
11. Android 开启“保持后台运行”后启动 `connectedDevice` 前台服务，同时持有 CPU 唤醒锁并取得 Wi-Fi 组播锁的使用权；UDP 扫描器也通过引用计数共享同一个底层组播锁。最后一个使用者退出时才真正释放组播锁，避免重复锁和提前释放。这样锁屏后 UDP 发现仍能接收组播，且不受 Android 15 `dataSync` 前台服务累计六小时限制。

## 状态边界

- “可信”与“在线”是两个概念：可信设备离线时不能发送消息或文件，但无需重新人工配对。
- 文件、消息和媒体入口只在 `online` 时开放。
- 解除配对同时关闭该设备的活动连接并取消未完成传输，但保留聊天历史和已完成文件。
- IP 只用于建立本次连接；历史和信任关系始终以设备 ID 为主键。
- 文件传输 socket 不改变设备连接状态，只有控制长连接驱动状态迁移。
- 独立文件 socket 会携带设备 ID、随机挑战和覆盖文件名、长度、校验值的 HMAC；接收端同时校验活动控制会话、来源 IP 和配对密钥，不能再仅凭同一 IP 获得文件写入权限。
- 媒体 socket 使用从配对密钥单向派生的独立密钥进行随机挑战应答；同一 IP 但没有正确密钥的连接不能触发来电，也不能伪造接听。只有双向认证完成后才接受音视频帧和屏幕共享数据。
- 升级前没有 `authKey` 的旧信任记录不会继续获得权限，需要重新配对；聊天历史、已完成文件和 SQLite 记录不受影响。

## 安全边界

- 当前认证可以阻止只从 UDP 广播获知设备 ID 的普通冒充，以及伪造文件请求或媒体呼叫。
- 配对密钥不会通过设备列表或日志暴露，但目前保存在本机应用设置中，网络数据仍为明文 TCP。
- 这不是对被动监听或中间人攻击的完整防护；正式跨不可信网络使用前仍需引入 TLS、设备公钥指纹或带人工验证码的密钥交换。
