# 网络集成测试

`transfermanager_integration_test` 会在同一进程中启动两个具有独立身份、设置、任务数据库和接收目录的 `TransferManager`。双方通过真实的本机 TCP socket 通信，不替换协议收发层。

当前覆盖以下链路：

1. 未配对 TCP 连接直接发送文本时，接收端拒绝报文且不向界面投递消息。
2. 首次配对被拒绝后，发起端回到 `unpaired`。
3. 再次配对并接受后，双方都建立可用的控制会话。
4. 配对双方生成并持久化相同的 256 位认证密钥；缺少密钥的旧版信任记录会失效。
5. 冒充已信任设备 ID、但无法提供正确 HMAC 的控制连接会被拒绝，且不能挤掉已有会话。
6. 主动中断控制连接后，双方通过挑战响应认证自动重连并收敛到唯一会话。
7. 重连完成后文本消息能够正常送达。
8. 冒充已配对设备发送文件报价时，因 HMAC 无效而被断开，且不会进入持久化任务数据库。
9. 发送 64 MB 文件时中断接收连接，重试后必须从非零偏移继续。
10. 中断后主动破坏 `.part` 内容，接收端必须检测到 SHA-256 不匹配、删除坏分片并自动从零重传一次。
11. 重传完成后同时检查双方 `verified` 状态、文件大小和 SHA-256。
12. 连续两次制造校验失败时只允许自动重试一次，随后进入终态，禁止无限重传。
13. 双方解除配对后都回到 `unpaired`，并取消未完成任务。
14. 已配对设备发起文件传输但停止发送数据时，接收端超时关闭 socket，将任务置为 `paused` 并保留可续传分片。
15. 对端声明远大于接收磁盘可用空间的文件时，接收端必须在创建 `.part` 前进入 `no-space` 并关闭连接，且不得把它保存为可恢复任务。

测试使用临时目录，不读取或修改用户的可信设备、聊天记录和传输任务。

通过项目构建脚本运行全部桌面测试：

```powershell
.\build-desktop.ps1 -QtRoot D:\QT\6.8.3\mingw_64 -MinGwBin D:\QT\Tools\mingw1310_64\bin
```

集成测试设有 60 秒超时。失败时会输出失败阶段、双方状态迁移以及当前控制会话方向，便于定位偶发网络竞态。
