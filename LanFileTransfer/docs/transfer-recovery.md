# 传输任务持久化与重启续传

## 持久化边界

文件任务保存在应用数据目录的 `transfers.sqlite3` 中，与聊天历史分离。每条任务以传输 ID 为主键，记录：

- 对端设备 ID、名称和最近一次连接地址；
- 发送或接收方向；
- 源文件地址或接收端 `.part` 路径；
- 文件名、真实大小和 SHA-256；
- 最终保存路径、进度、状态和更新时间。

已完成、取消以及不可自动恢复的读写或校验错误不会在启动时自动排队，但记录仍保留用于任务历史。

## 恢复流程

1. 新发送任务在计算校验值之前落库，避免校验期间异常退出丢失任务。
2. 接收文件创建 `.part` 后立即落库，并持续保存进度状态。
3. 应用启动时，将上次处于校验、连接或传输中的任务统一标记为 `paused`。
4. 发送任务重新校验源文件；文件缺失或内容变化时停止自动恢复并显示读取错误。
5. 可信设备进入 `online` 后，发送端使用原任务 ID 和校验值重新发送 `FileOffer`。
6. 接收端按任务 ID 找到原 `.part`，返回实际文件长度；发送端从该偏移继续。
7. 单个传输连接意外断开但控制连接仍在线时，最多按指数退避自动重试五次。
8. 用户取消任务后，发送任务停止排队；接收任务同时删除未完成的 `.part`。
9. 如果接收端已经校验完成但最终确认包丢失，再次收到相同任务 ID 时直接返回完成确认，不重复下载文件。
10. 出站 TCP 连接 15 秒内未建立则主动回收；未发送首包的入站连接、等待配对确认的控制连接和停止产生网络进度的文件连接分别按阶段超时，避免任务永久卡在连接或传输状态。
11. 大文件完成后的 SHA-256 校验使用独立的十分钟窗口，不会被普通传输空闲超时误杀。
12. 接收文件前检查临时目录所在文件系统的可用空间，并预留 16 MiB 安全余量；容量不足时不创建或扩展 `.part`，接收端显示 `no-space`，发送端进入不可自动重试的 `rejected` 终态。

## 一致性规则

- 设备身份始终使用设备 ID，IP 只作为本次连接端点。
- 相同任务 ID 的设备、文件名、大小或校验值不一致时按协议错误拒绝，避免拼接错误文件。
- 重启恢复只复用数据库记录的任务 ID；不会创建新的聊天消息或重复任务条目。
- 接收偏移以磁盘上的 `.part` 实际大小为准，不相信数据库中的显示进度。

## 当前限制

- Android 发送端使用系统 `ACTION_OPEN_DOCUMENT` 多选器，并在返回时保存源文件的长期读取授权，因此正常文档提供器返回的 `content://` 文件可以跨重启续传。少数不支持长期授权的第三方提供器仍只能保证本次进程内可读，日志会记录该兼容性降级。
- 当前恢复粒度是文件偏移；校验失败后的分块修复仍属于后续传输成熟化工作。

## 自动化验证

网络集成测试会在真实本机 TCP 连接上传输 64 MB 文件，在收到部分数据后主动中断文件 socket，并验证重试协商返回非零偏移、最终文件大小及 SHA-256 一致。测试说明见 `network-integration-tests.md`。
